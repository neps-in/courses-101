# M01.L03 Quiz — Install WordPress, turn on HTTPS and tour the dashboard

> 7 questions · 3 recall, 3 scenario, 1 spot-the-error · includes 1 spaced-review question from M01.L02.
> Menu names checked against WordPress 7.1 on 2026-10-29.

### Q1. Which three things does every WordPress installation need?
- a) A theme, a plugin and a domain
- b) WordPress's files, a MySQL/MariaDB database and an admin account
- c) A page builder, a CDN and an SSL plugin
- d) A WordPress.com account, a Google account and a domain

**Answer:** b
**Explanation:** WordPress runs from its files, stores content in a database, and needs at least one admin account to manage it. One-click installers, Local and Playground create all three. Themes come built in; plugins, CDNs and page builders are optional; no outside accounts are needed.
**Hint:** What do the installers set up for you?

### Q2. Where in the dashboard do you check that both the WordPress Address and the Site Address use `https://`?
- a) Tools → Export
- b) Settings → General
- c) Appearance → Editor
- d) Users → Profile

**Answer:** b
**Explanation:** **Settings → General** holds the WordPress Address (URL) and Site Address (URL). Tools → Export exports content, Appearance → Editor changes design, and Users → Profile is your own account.
**Hint:** It's the same screen as the site title and timezone.

### Q3. You can't find a menu this lesson mentions. What's the fastest way to reach it in WordPress 7.x?
- a) Reinstall WordPress
- b) Press Ctrl+K (or ⌘+K on a Mac) and search for it by name
- c) Install a "menu finder" plugin
- d) Switch to a different theme

**Answer:** b
**Explanation:** The command palette searches dashboard screens and tools by name. Menus move between releases and plugins can add their own, so searching is faster than hunting. No reinstall, plugin or theme change is needed.
**Hint:** It's a keyboard shortcut, not a setting.

### Q4. Dev hasn't bought hosting yet but wants a permanent practice site he can work on offline for the whole course. Which install method fits best?
- a) WordPress Playground in a private browser window
- b) Local on his computer
- c) A host's one-click installer
- d) Installing by hand on a free hosting trial

**Answer:** b
**Explanation:** Local is free, keeps the site permanently on his computer and works offline. Playground is meant for quick experiments (and a private window loses it on close). A host's installer needs paid hosting, and a manual install on a trial is slow and temporary.
**Hint:** Which option is free, permanent and works without the internet?

### Q5. Leena's host shows an active Let's Encrypt certificate, but Chrome still says "Not secure" on her new site. Settings → General shows both addresses starting with `http://`. What should she do?
- a) Install three SSL plugins to be safe
- b) Buy a paid certificate
- c) Confirm `https://herdomain` loads with a padlock, then change both addresses to `https://` (or use Site Health's HTTPS option)
- d) Delete the site and reinstall

**Answer:** c
**Explanation:** The certificate works; WordPress just doesn't know to use it. Checking that the HTTPS address loads first avoids a lockout, then updating both addresses (or using Site Health's one-click option when offered) fixes it. Paid certificates, extra plugins and reinstalling don't address the cause.
**Hint:** The certificate is fine; what does WordPress still think its address is?

### Q6. Spot the error: Sam's install checklist says:
> 1. Install with the host's one-click installer and choose `https://`.
> 2. Username: `admin`, so it's easy to remember.
> 3. Password: generated by a password manager.
> 4. Check the padlock and both addresses in Settings → General.

Which step is wrong?
- a) Step 1
- b) Step 2
- c) Step 3
- d) Step 4

**Answer:** b
**Explanation:** `admin` is the first username attackers try in automated login attacks. A unique username makes those attacks much harder, especially combined with the generated password in Step 3. The other steps are all good practice from this lesson.
**Hint:** Which step makes an attacker's job easier?

### Q7. (review: m01-l02) After installing WordPress on new hosting, Rina's friend still sees the domain's old parked page, while Rina sees the new site. What's the most likely reason?
- a) WordPress didn't install correctly
- b) The friend's DNS resolver is still using the cached old A record until its TTL expires
- c) The certificate is invalid
- d) Rina chose the wrong theme

**Answer:** b
**Explanation:** As in M01.L02, DNS answers are cached for up to the record's TTL, so some people keep seeing the old destination for a while. The install and certificate can be fine; the friend's resolver just hasn't asked again yet.
**Hint:** Remember what TTL controls.
